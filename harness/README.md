# kicad-perf measurement harness

Scaled-up measurement stack for KiCad — wall time, CPU cycles, RAM
(peak + curve + fragmentation), GPU (draw calls + engine %), and
UI-interaction latency. Designed to give per-scenario deltas across
{stock 9.0.8, stock master @32fcb08d, patched master (this repo)}.

## Why this exists

The first 56 patches in this repo are all CPU/latency wins found by
reading the code. Real optimization needs the ↕ that only running the
system produces: which axis actually matters on real designs, where
the regressions hide, whether a "5-30 ms" estimate holds up on a
5000-footprint board with a 100-sheet hierarchy.

## Scope

### Measured axes

| axis            | source                                                              |
|-----------------|---------------------------------------------------------------------|
| wall time       | hyperfine (whole-invocation) + `KI_PERF_TRACE=1` phase timers       |
| CPU cycles      | `perf stat -e cycles,instructions,cache-misses,branch-misses`       |
| user/sys CPU    | `getrusage(RUSAGE_SELF).ru_utime / ru_stime`                        |
| peak RSS        | `getrusage(RUSAGE_SELF).ru_maxrss`                                  |
| RSS/heap curve  | `/proc/self/statm` polled at 50 Hz by side-car; `malloc_info(3)`    |
| mmap footprint  | `/proc/self/smaps` parsed for named regions (fonts, textures)       |
| heap detail     | `heaptrack` (userspace-extracted) for periodic full-run captures    |
| GPU draw calls  | `LIBGL_DEBUG=verbose` + GL passthrough shim that logs per-frame     |
| GPU engine %    | `radeontop -d -` / `intel_gpu_top -J` / `nvidia-smi dmon` (host)    |
| UI framerate    | `KI_UI_FRAME_TRACE=1` env, kicad emits one line per swap-buffer     |

### UI scenarios (each driven by scripted xdotool)

Grouped by editor.

**pcbnew:**
1. Cold start → first paintable frame
2. Load `starfish.kicad_pcb` (5 MB) → time to interactive
3. Pan diagonal across whole board → sustained fps + GPU util
4. Zoom in 8 levels → per-zoom frame time
5. Drag a mid-size footprint 500 px → CPU spike + rebuild time
6. Toggle every layer visibility 3× → GAL re-batch cost
7. Refill zones → wall + peak RAM
8. Run DRC → wall + peak RAM
9. Open Footprint Library Browser → time to first FP
10. Save-as → wall + write throughput

**eeschema:**
1. Cold start → first paintable frame
2. Open a 100-sheet hierarchy → time to first draw
3. Switch sheet, back, switch → cache hit vs miss frame time
4. Annotate all → wall + CPU
5. ERC → wall + peak RAM
6. BOM export → wall
7. Netlist export → wall

**kicad-cli** (regression coverage from existing baseline):
1. `--version` (fixed init)
2. `pcb export svg -l F.Cu <board>` (fast-path from P3)
3. `pcb export gerbers <board>` (multi-file plot)
4. `pcb export pdf <board>` (zlib fast-path from P25)
5. `pcb export step <board>` (OCC exporter)
6. `sch export bom <sch>` (schematic-plot fast-path from P45)
7. `sch export pdf <sch>`
8. Daemon: 15 exports (measures amortized init)

## Layout

```
harness/
  README.md                 (this file)
  DESIGN.md                 (deeper design notes and cross-references)
  scenarios/                one Python driver per scenario
    pcbnew_load_starfish.py
    pcbnew_pan.py
    …
  collectors/               instrumentation side-cars
    rss_sampler.c           50 Hz /proc/self/statm sampler → CSV
    gl_shim.c               LD_PRELOAD wrapper counting glDrawArrays/glDrawElements
    perf_stat_wrapper.sh    perf stat around a command
    hyperfine_wrap.sh
  runner.py                 top-level orchestrator: N runs × scenarios × binaries
  reports/
    template.md             the comparison table above
    render.py               takes runner output → filled Markdown + JSON
  fixtures/                 curated test boards / schematics
    starfish.kicad_pcb      symlinked from kicad-references
    100-sheet-hier.kicad_sch (synthetic; generated by fixtures/gen_hier.py)
```

## Constraint reality

This box is headless aarch64, no sudo, no `perf`/`Xvfb`/`xdotool`/
`heaptrack` installed. `apt-get download` + userspace extract into
`~/local/wx-root/` lets us pull the userspace-only bits. `perf` needs
`kernel.perf_event_paranoid <= 2` — if the host disallows this the
harness falls back to `getrusage`+`/proc/self/statm` only and logs
"perf unavailable" in the report.

For **GPU** on this specific host, no GPU tools are available; the
GL-shim gives draw-call counts but engine-utilization numbers only
come from a machine that has the real vendor tools. The report layout
handles both cases.
