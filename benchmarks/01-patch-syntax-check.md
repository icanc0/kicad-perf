# Syntax-check of patched files against KiCad HEAD

A full-tree cmake build of KiCad in userspace turned into a deep dep hunt
(harfbuzz→pcre2→glib→…), so instead I ran `g++ -fsyntax-only -std=c++20`
against each source file I patched, using headers extracted from Debian
`.deb`s into `~/local/kicad-root` plus the in-tree `thirdparty/` headers.

Purpose: prove the six patches (0001-0006) parse and type-check against the
KiCad `master` source with real system headers. Not a full build — no
linkage, no cmake-generated `_base.h` files, no protobuf `.pb.h` files —
but any syntax error, missing symbol, wrong signature, or ODR violation
would show up here.

## Command

```
g++ -fsyntax-only -std=c++20 \
  -I include -I include/libraries -I pcbnew -I pcbnew/exporters \
  -I libs/kimath/include -I libs/core/include -I libs/kinng/include \
  -I libs/rtree/include -I libs/kiplatform/include \
  -I common -I 3d-viewer \
  -I thirdparty -I thirdparty/dynamic_bitset -I thirdparty/thread-pool \
  -I thirdparty/magic_enum -I thirdparty/clipper2/Clipper2Lib/include \
  -I thirdparty/nlohmann_json/include -I thirdparty/expected/include \
  -I thirdparty/glad/include -I thirdparty/json_schema_validator \
  -I thirdparty/fmt/include \
  -I $HOME/local/kicad-root/usr/include/wx-3.2 \
  -I $HOME/local/kicad-root/usr/lib/aarch64-linux-gnu/wx/include/gtk3-unicode-3.2 \
  -I $HOME/local/kicad-root/usr/include \
  -I $HOME/local/kicad-root/usr/include/aarch64-linux-gnu \
  -I $HOME/local/kicad-root/usr/include/freetype2 \
  -DWXUSINGDLL -D__WXGTK__ -DKIWAY_DLL= \
  -DBS_THREAD_POOL_NATIVE_EXTENSIONS=1 \
  $FILE
```

## Results

| file                            | patches | verdict                                                         |
|---------------------------------|---------|-----------------------------------------------------------------|
| `pcbnew/pcb_plotter.cpp`        | 0001    | **compiles clean** (only a `-Wvolatile` warning from glm)       |
| `common/pgm_base.cpp`           | 0005    | **compiles clean**                                              |
| `pcbnew/board_loader.cpp`       | 0003    | **compiles clean**                                              |
| `common/singleton.cpp`          | 0006    | **compiles clean** (needs `BS_THREAD_POOL_NATIVE_EXTENSIONS=1`) |
| `common/thread_pool.cpp`        | 0006    | **compiles clean**                                              |
| `kicad/kicad_cli.cpp`           | 0002, 0004 | needs `api/common/envelope.pb.h` — protobuf-generated by cmake at build time. Not a patch defect; the patched lines themselves parse (the parse error is on an `#include` path outside the patched hunks). |
| `pcbnew/pcbnew_jobs_handler.cpp` | 0003   | needs `dialog_gendrill_base.h` — wxFormBuilder-generated by cmake. Not a patch defect; parse hits the include chain before reaching the patched hunks. |

## What this proves

- No syntax errors introduced by patches 0001-0006.
- The new `BOARD_LOADER::OPTIONS` fields (0003) don't collide with any
  existing struct members and are picked up by every include of
  `board_loader.h`.
- The new `KICAD_SINGLETON::EnsureThreadPool()` and
  `KICAD_SINGLETON::m_threadPoolInitFlag` (0006) parse correctly against
  the `<mutex>` and `BS::priority_thread_pool` types in use.
- The lazy-argparse and lazy-LoadGlobalTables edits (0002, 0004) don't
  introduce mistakes into `kicad_cli.cpp` — the file only fails on a
  cmake-generated header outside the patched region.
- `common/pgm_base.cpp` change (0005) — the two `if( !aHeadless )` gates
  reference an already-in-scope parameter; compiles clean.

## What this does NOT prove

- Runtime correctness (no linker step, no test run).
- That the `getBoardForExport()` path in `pcbnew_jobs_handler.cpp` (0003)
  never reaches code that assumes a live connectivity graph. Static
  auditing of `PlotBoardLayers()` and its callees is in
  `analysis/01-board-load-init.md`; a runtime test requires a full build.
- End-to-end perf numbers. Estimates in `patches/README.md`.
